## The rule that could not see past the hook

React Hook Form is very often not called in the component that renders the
fields. It is called once inside a project's own hook — `useCheckoutForm`,
`useSignupForm` — which returns the form state for a component to spread
across its inputs.

To two of shadscan's rules, that looked like nothing at all. The component
rendering the fields had no `useForm` call in it, so `validation-wired-to-form`
saw a form with no validation attached and said so. `field-errors-rendered`
had the mirror-image problem: it found the form where it was created, in a hook
with no JSX, and reported that nothing rendered the errors.

Both were wrong, and wrong in the worst way — an application doing the right
thing was told it had done the wrong one. That was
[issue #32](https://github.com/TheOrcDev/shadscan/issues/32).

## Following the hook

The rules now trace a project-owned hook from where the form is built to where
it is used, and evaluate each half where it actually lives. Validation is
judged in the hook that configures the resolver. Rendered field errors are
judged in the component that renders the fields. A provider hook is no longer
expected to render error UI that is not its job, and a consumer is no longer
blamed for validation it did not configure.

Only project-owned hooks are followed. A hook from a dependency is somebody
else's code, and shadscan does not audit it.

## What happens when the trail runs cold

Not every hook can be followed. A hook selected at runtime, a form returned
through a dynamic value, or a chain that leaves the project boundary — none of
those can be resolved statically, and pretending otherwise is how a scanner
starts inventing findings.

Where the flow cannot be resolved, the result is **advisory** rather than a
failure. It is reported so you can look, but it does not move the score, and
it never borrows evidence from an unrelated form elsewhere in the project to
justify a verdict about this one.

## What to expect on upgrade

If you build forms inside custom hooks, your score will go up on this release
with no change to your code — those two rules were failing on an idiom that was
never wrong. If you do not, nothing moves.

The bundled ruleset advances to `2026.08.45`, which is how a report explains
why the same project scores differently than it did yesterday.
