## The row that was always selected

A command palette opened, every row carried the same background, and the code
looked right at first glance. The item used `data-selected:bg-muted`, which
reads like “apply this when selected.” In this case it means something else:
“apply this whenever the attribute exists.”

cmdk renders that attribute for every item. The selected row gets
`data-selected="true"`; every other row gets `data-selected="false"`. A
presence selector matches both, so the palette paints every row as selected.
The same trap exists for `data-disabled`.

## A boolean attribute that never disappears

The safe spelling tests the value:
`data-[selected=true]:bg-muted`. Named group selectors need the same treatment,
for example `group-data-[selected=true]/command-item:text-foreground`.

Modern shadcn projects can keep the shorter spelling because
`shadcn/tailwind.css` defines `data-selected` and `data-disabled` as
value-aware custom variants. That means a useful rule cannot reject one token
in isolation. It has to know which primitive renders the attribute and which
Tailwind contract the application actually loads.

## Detect the contract, not a spelling

`cmdk-item-state-variants-use-values` is deliberately specific to cmdk. Other
component libraries may omit a data attribute when its state is false, where a
presence selector is exactly right. The rule first finds a project-owned cmdk
item, then checks its selected and disabled variants.

It accepts explicit true-value selectors. It also starts from the configured
Tailwind stylesheet, follows reachable local imports, recognizes shadcn's
package contract and value-aware custom variants, and applies later overrides
in source order. If that stylesheet graph is missing, unreadable, too large or
too repetitive to analyze safely, the result becomes advisory instead of a
confident failure.

## Tested against the bug that prompted it

The rule was run against `justfuckinguseshadcn`, the project where the visual
regression appeared. Its fixed command item uses explicit `=true` variants and
passes at **100/100**. In a disposable copy, changing the selected background
back to `data-selected:bg-muted` produced a high-confidence finding on the
exact component line and moved the audit to **98/100**.

The focused suite also covers aliases, named groups, module-level class
constants, custom-variant overrides, quoted and commented CSS, cyclic and
repeated imports, unsafe paths, missing files and resource limits. The rule is
narrow because the underlying contract is narrow; that is what lets it affect
the score without guessing.
