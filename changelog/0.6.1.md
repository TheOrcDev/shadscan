## A separator in the wrong alphabet

Globs speak forward slashes on every platform. Windows paths do not.
Several App Router rules built their match patterns with `path.join`,
which on Windows produces `app\dashboard\**\page.tsx` — a string the glob
matcher will never match against anything.

The result was not an error. The rules simply found no route boundaries
and no metadata exports, concluded the project did not have them, and
scored it accordingly. A Windows user and a macOS user could audit the
same commit and get different grades, with nothing in either report to
suggest why. Silent wrong answers are the worst kind for a tool whose
entire promise is a deterministic score.

The fix normalizes the separators before the patterns reach the matcher,
so the glob always sees the alphabet it expects.

## Why this is its own release

This landed after 0.6.0 was cut, so it missed that build. It also
arrived without a ruleset bump: the contribution branched before
`2026.07.39` existed, and merging placed it on the same number 0.6.0 had
already shipped. Two different rule behaviors under one ruleset
identifier defeats the point of having the identifier, so this release
advances it to `2026.07.40`.

If you scan on Windows, upgrade — your previous scores were understated.
If you scan on macOS or Linux, nothing changes.
