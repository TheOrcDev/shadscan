## Ask, don't parse

Agents already use shadscan — the `--prompt` handoff and `--apply` exist
for exactly that. But both hand the agent everything at once, and an agent
mid-task rarely wants everything. It wants the answer to one question:
"which accessibility problems are left in `apps/web`?"

`shadscan mcp` makes that a tool call. The server speaks the Model
Context Protocol over stdio, and setup is one line:

```
claude mcp add shadscan -- npx -y @shadscan/cli mcp
```

Three tools, all read-only. `scan` returns the score, the grade, and the
actionable findings — each with its suggested fix, acceptance criteria,
and score impact — filterable by category, severity, or workspace
package. `list_projects` classifies a monorepo's packages the way
`--list-projects` does. `explain_rule` describes what one rule checks,
and guessing an id wrong answers with the nearest real ones.

## The server that refuses to remember

The obvious design was a cache: scan once, let the agent query what is
still broken. That design was measured and rejected. A scan takes about a
second, and shadscan is deterministic over the state of your files — so
the moment an agent edits one, any remembered answer is wrong, at
precisely the moment the agent most needs the truth.

So every call re-scans. Fix something, call `scan` again, read the delta.
The loop is honest because it never answers from memory, and cheap
because the engine is fast. Responses carry the engine, ruleset, and
schema versions, so results from different shadscan versions can never be
silently compared.

## Small on purpose

The server can only read inside the directories it was started with;
tool calls cannot widen that. It never writes files, never touches the
network, and strips the roast copy — agents quote tool output verbatim,
and a roast belongs in your terminal, not your commit message.

The protocol SDK is bundled at build time rather than added as a
dependency, so the published package still installs the same six runtime
dependencies it did before. The packed-package smoke test now audits the
shipped bundle to keep the SDK's HTTP transports — an entire server
stack a stdio process never uses — from ever reaching your
`node_modules`, and drives a real protocol session against the packed
artifact so a stray print onto the protocol stream cannot ship.
