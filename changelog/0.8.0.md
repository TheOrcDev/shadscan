## The problem was silence

Shadscan resolves your project, works out its structure, evaluates fifty-nine
rules against your components, and assembles a report. On a large codebase
that takes long enough that people assumed it had hung, and reached for
Ctrl+C. The tool was working the whole time; it just never said so.

```
✓ Resolving project
✓ Discovering app structure
⠹ Evaluating UI rules
  Preparing report
```

The active phase spins, then settles into a tick and stays on screen. Four
phases, always the same four, for single projects, monorepo workspaces, and
`shadscan setup` alike.

## No percentages, on purpose

A progress bar would have to guess. Rules vary enormously in cost — one reads
a single manifest, another walks the render graph across every route — so any
"73%, about 4 seconds left" would be invention dressed as measurement. For a
tool whose entire claim is that it reports what it can prove, that seemed like
the wrong thing to add. Naming the current phase is something shadscan
actually knows.

## It stays out of the way of machines

Progress is written to stderr, never stdout, and disables itself for JSON and
prompt output, in CI, when either stream is piped or redirected, when stderr
is not a terminal, under `--no-interactive`, and with
`SHADSCAN_INTERACTIVE=0`. Scripts parsing the JSON report, the GitHub Action,
and `--fail-under` score gates behave exactly as they did in 0.7.0.

Plain terminals are handled too: no Unicode means `[ok]` and a `-\|/` spinner,
no colour means no escape codes. There are no new dependencies, the animation
timer is unreferenced so it can never hold the process open, and if writing to
the terminal ever fails the progress display switches itself off rather than
turning a cosmetic problem into a failed scan.

## One change under the surface

The audit loop now yields to the event loop between rules, so the animation
keeps moving during synchronous syntax-tree work. Rules still run one after
another in the same order, so scores are unchanged and reruns stay identical.
The same change makes cancellation land sooner, which the hosted API's
timeouts benefit from.

A single unusually slow rule can still pause the spinner briefly. Moving the
audit onto a worker thread would fix that completely, at the cost of worker
bundling, report serialization, and extra packaging risk — too much to spend
on an animation.
