## A command, not a flag per bug

Last release added `--check-overflow`: open the running app, fail if the page
scrolls sideways. The check was right and the name was too small. Horizontal
overflow is the first thing worth checking in a real browser, not the only one,
and naming the command after one bug means a new flag for every bug after it.

So the public entry point is now `--check-ui`, with overflow as its first
check and room for the next ones under the same roof.

```
shadscan --check-ui http://localhost:3000 --route /docs --route /pricing
```

`--check-overflow` keeps working. Nothing you already wrote into a CI job
breaks.

## The prompt stopped only reading your code

The copy-paste prompt has always handed an agent a deterministic source audit.
That leaves out everything a browser knows.

It now pairs the audit with rendered verification, and it works out what to
verify rather than being told: every application it detects, including each app
in a monorepo, the concrete local pages those apps actually serve, and any
production deployment it can confirm. Large route lists are batched instead of
being run one at a time.

The part that matters most is what it does when it *cannot* look. A page behind
a login, a route that only exists for a signed-in user, a deployment it cannot
confirm — those are reported as uncovered. It does not invent a plausible URL,
and it does not describe a partial run as a clean one. An agent that quietly
skips half your app and reports success is worse than one that checks nothing.

## Following a redirect without following it anywhere

Point a rendered check at `example.com` and the server may well send it to
`www.example.com`. Refusing to follow that makes the check useless on most real
deployments; following redirects freely makes it a tool that can be pointed at
anything.

So the redirect handling is deliberately narrow: a conventional two-label apex
host to its own `www`, or HTTP to HTTPS. The resolved origin is then pinned for
every route in the run. An HTTPS downgrade, an unrelated origin, a project
subdomain, or a client-side cross-origin navigation stays blocked.

## Nothing about your score changes

The bundled ruleset stays at `2026.08.45`, the rule catalog is unchanged, and
the report schema is unchanged. Rendered checks still add no rule, no points,
and no grade — they are a separate gate, deliberately kept out of a number that
is supposed to depend only on your files.
