## Composition contracts, checked

shadcn components are composition contracts: items belong in groups,
`InputGroup` provides its own input and addon parts, and an `Alert` is built
from a leading icon, a title, and a description. A new anatomy engine encodes
those contracts declaratively and checks them across your JSX — starting with
three advisory rules that never move your score while they earn trust.

Two design decisions keep them honest. Anatomy is resolved against the
components your project actually vendors, so a part you added to your own
`components/ui/alert.tsx` is part of the contract, not a violation. And
composition that crosses component boundaries — an item rendered by a helper,
children passed through props — is treated as unknowable rather than wrong.

## The audit in your CI

The repository now doubles as a composite GitHub Action. Point a workflow at
`TheOrcDev/shadscan`, and every push gets a deterministic score with a
category table in the job summary. Add `fail-under` to gate merges, and
enable `create-issue` to keep a single tracked issue up to date — its body
embeds the same paste-ready remediation handoff `--prompt` generates, so
assigning the issue to a coding agent hands it a complete plan.

## The ruleset, in the open

Every rule shadscan runs is now documented on the public rules page,
generated from the same catalog the CLI bundles, and releases are published
on the changelog page you are reading. Both are a keyboard shortcut away
behind the site's command menu.
