## A control that looks like one thing and focuses like two

Put an email field and a Subscribe button in a `ButtonGroup` and you get a
single pill: one border, rounded ends, no seam. Then someone clicks into the
field, and the focus ring wraps the input and stops dead where the button
starts — square-cornered on the right, with the button hanging outside it. The
control looks like one object at rest and two objects on focus.

Nobody wrote that bug. It falls out of what `ButtonGroup` is for.

## Why it happens

`ButtonGroup` joins its children by squaring off the inner corners and
dropping the inner borders. Its entire answer to focus is to lift whichever
child has focus above its neighbours, so that child's own ring paints over the
adjacent border instead of being clipped by it.

For buttons, that is exactly right. Every segment in a segmented control has
the same shape and the same ring, so lifting the focused one reads as *this
one*. For a text input it falls apart, because the input's ring is drawn
around the input's own box — including the edge pressed flush against the
button. The ring ends up running down the middle of the pill.

## The fix is a different component, not a patch

shadcn already ships the right one. `InputGroup` puts the focus treatment on
the **wrapper** and has the inner control give up its own ring, so focusing the
field lights the entire shape — field, button, and the seam between them — as
one object.

So the new rule does not ask you to patch `ButtonGroup`. It tells you that a
text input has ended up in the component built for joining buttons, and points
at the one built for attaching things to an input.

## Built against real code

The rule looks through whatever wraps the control. In practice a text field is
almost never a direct child of the group — it sits inside a form primitive
first — and a rule that only checked direct children would have found nothing
in any real project we tested.

It is deliberately quiet. `ButtonGroup` is an open container that legitimately
holds buttons, selects, separators and arbitrary wrappers, and radio,
checkbox and submit inputs carry no ring of their own. None of those are
reported. Only text entry is.

## Advisory, on purpose

It ships as an advisory, so it appears in your findings and in the agent
handoff without changing your score. Across nine real shadcn projects it found
four instances and flagged nothing it should not have — but those nine share
one author, which is not yet a wide enough sample to justify moving everyone's
score for what is, in the end, a cosmetic defect. It has to earn that.
