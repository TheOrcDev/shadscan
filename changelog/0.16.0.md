## Silence reads as failure

The source audit is fast enough that nobody wonders whether it hung. A
rendered check is not: it starts a browser, resolves the target, loads each
route, and lays every one out at two viewports. That is several seconds where
a terminal showing nothing looks indistinguishable from a terminal that has
stopped.

`--check-ui` now shows its work, in the same three phases it actually performs:

```
Resolving UI target
Checking mobile and desktop layouts
Preparing UI report
```

The checklist appears immediately rather than after the first phase finishes,
and completed phases stay on screen. This is the treatment interactive scans
have had since 0.8.0, applied to the check that needed it more.

## Quiet whenever something is reading

Progress output is for a person watching a terminal, and for nobody else.

It goes to **stderr**, never stdout, so a piped or redirected report is
byte-identical to before — the contract that lets `--json` be consumed by a
script without filtering anything out. And it suppresses itself entirely under
`--json`, in CI, under `TERM=dumb`, when stderr is not a terminal, and when you
pass `--no-interactive`.

The rule of thumb is unchanged from the audit's own progress: if anything other
than a human is likely reading, print nothing.

## Nothing else moves

No new rule, no scoring change, no schema change. The bundled ruleset stays at
`2026.08.45`. This release only affects what you see while a check is running,
not what it decides.
