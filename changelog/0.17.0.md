## Earning the right to matter

`button-group-holds-only-buttons` shipped in 0.10.0 as an advisory. It caught
a real defect — a text input joined to a button inside `ButtonGroup`, where the
focus ring wraps the input and stops dead where the button begins — but it had
only been checked against one author's projects, which is not enough evidence
to start moving other people's scores.

It is now worth **two points**, and it is stricter about what it will penalise.
It evaluates compositions that are actually mounted on a render surface rather
than any that appear in source, and anything it cannot prove — a customized
`ButtonGroup`, a composition it can only partly resolve — is reported as an
advisory instead of costing you anything.

It also follows more of the ways people build forms: shadcn's `FormField`
render prop, and bare react-hook-form `Controller`, which is what `FormField`
wraps and what plenty of projects reach for directly.

## The provider that hid an entire app

Promoting the rule surfaced something worse than the rule itself.

Rendered-surface analysis walks from a route down through everything it
renders. When it met a component it could not see inside — a provider from a
package, wrapping `{children}` — it stopped. In one real project, a single
`NuqsAdapter` in the root layout meant the scanner reached **one file in the
entire application**, and reported that surface as *complete* while doing so.
Nothing downstream could tell that the evidence was missing.

Expansion now continues through wrappers that are known to render their
children and nothing else: React's own `Suspense`, `Fragment`, `StrictMode`
and `Profiler`, and the `nuqs` adapters, joining the `next-themes` and Radix
navigation cases already handled. In that same project the scanner went from
one file to twenty-four.

This is not a `ButtonGroup` fix. Any rule that reasons about what a route
actually renders was working from the same truncated picture.

## What it still cannot see

A provider written **in your own project** whose children projection cannot be
proven still stops expansion. The difference is that those surfaces are marked
incomplete, with the reason attached, rather than passed off as complete.

That honesty matters more than the coverage: a rule that knows what it has not
seen can stay quiet, and a scanner that quietly guesses is worse than one that
admits a gap.

## What to expect on upgrade

If you join a text input to a button inside `ButtonGroup` on a page that
actually renders, you will lose two points and get told where. The remedy is
`InputGroup`, which is shadcn's component for exactly that composition and
lights the whole control on focus rather than half of it.

The bundled ruleset advances to `2026.08.46`.
